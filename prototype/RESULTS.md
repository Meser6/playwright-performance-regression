# Prototype results: V-01 to V-12

Throw-away spike for work package WP-02. It answers the assumptions V-01 to V-12 with the
smallest possible code. The directory is not part of the package; the PR that adds it is closed
without merging.

## Setup

| Item | Value |
|---|---|
| Date | 2026-11-18 |
| Playwright | 1.57.0 (repository dev dependency) and 1.65.1 (`npm view @playwright/test version`) |
| Browsers | Chromium (both versions), WebKit (both), Firefox (1.65.1 only, see "Not verified") |
| Node | 24.2.0 for every Playwright run; V-07 also on 22.18.0 (minimum in `engines`) |
| Host | macOS (Darwin 27.2), arm64, local runs only |

Layout:

- `server.mjs`: `node:http` demo server on two ports (two origins), endpoints with controllable
  delays (`/api/delay?ms=N&preflightMs=N`), `/page`, `/api/hang`.
- `projects/_shared/`: minimal `withPerf()` stand-in (`with-perf.cjs`), the registry in
  `globalThis[Symbol.for(...)]` as an ESM and a CJS copy, a recording reporter and a collector
  fixture (`context` override with a request tracker, auto `_perfBuffer`, attachment in teardown).
- `projects/esm-ts`, `projects/cjs-js`: ESM and CJS sample projects (V-01, V-02, V-05, V-06,
  V-07, V-10, V-11); `projects/browsers` (V-08, V-09, V-12 a/e); `projects/conditions`
  (V-12 b/c/d); `projects/volume` (V-04).
- `checks/*.mjs`: one function per V item; `verify.mjs` runs them for each Playwright version
  and writes the raw evidence to `results/1.57.0.json` and `results/latest.json`.

Run: `npm run setup` (installs both Playwright versions and browsers), then
`node verify.mjs [--version 1.57.0|latest] [V-01+V-02 V-03 ...]`. V-07 also uses the Node binary
in `PROTO_NODE22` when set.

## Results

Unless stated otherwise, the result is the same on 1.57.0 and 1.65.1.

| V | Assumption (short) | Result | Evidence | Consequence for the implementation |
|---|---|---|---|---|
| V-01 | Workers load the Playwright config again, so `withPerf()` fills the registry in the worker before fixtures run | confirmed | 16 runs per version (ESM/CJS, TS/JS configs, perf mode on and off): the registry read in the fixture (worker pid) deep-equals the one read in the reporter (main pid). Written by the CJS copy, read by the ESM copy and by `globalThis` directly: `Symbol.for` gives one shared slot. Perf mode off: registry empty in both processes | Registry via `globalThis[Symbol.for(...)]` works as designed; no fixture option needed |
| V-02 | Playwright transpiles the package config `.ts` imported from the Playwright config, in ESM and CJS projects | confirmed | ESM project: TS config imports `./pw-perf.*.config` (extensionless) whose module imports a helper with `.ts`, without extension and via a `tsconfig` `paths` alias: all pass. CJS project: same three plus a `.js` config that `require()`s `./pw-perf.plain.config` and `./pw-perf.plain.config.ts`: all pass. In a CJS `.js` config the TS default export arrives as `{ default }` | Documented setup works as specified. Docs for CJS JS configs: `require('./<pkg>.config').default` |
| V-03 | The Playwright CLI can be found from the project directory via `bin` of `@playwright/test` | confirmed | `createRequire(<dir>/noop.js).resolve('@playwright/test/package.json')` works from the project root and a nested directory; `bin` is `{"playwright":"cli.js"}` in both versions; `package.json` is in `exports`. `spawn(process.execPath, [cli, 'test', ...], { shell: false })` runs from a path with a space. Without Playwright installed: `MODULE_NOT_FOUND`, `Cannot find module '@playwright/test/package.json'` | 04-REQ-13 as specified; map `MODULE_NOT_FOUND` to `CLI_PLAYWRIGHT_NOT_FOUND` |
| V-04 | Attachments with several thousand samples per test do not noticeably slow Playwright's IPC or reports | confirmed | 5 tests per run, synthetic samples of the 02 shape (~264 bytes each). Per test at 0 / 1000 / 5000 / 20000 samples: attachment 0.2 KB / 265 KB / 1.3 MB / 5.3 MB; worker `JSON.stringify` 0 / 0.4 / 1.8 / 6.8-8.2 ms; `attach()` to `onTestEnd` (median) 3 / 16-24 / 41-48 / 105-131 ms, max 156 ms; `JSON.parse` in the reporter 0.01 / 0.4 / 1.9 / 7.4-9.6 ms. Whole run with `dot`: 0.61-0.71 s at 0 vs 0.78-0.93 s at 20000 samples per test. With the HTML reporter as well: 0.84-1.07 s vs 1.25-1.62 s; the report grows from 0.5 MB to 1.9 MB | The 20 000 per-test limit (05-REQ-16) is safe: about 0.1 s of IPC per test at the limit. No compact format needed |
| V-05 | `--reporter` replaces the config reporters; appending our path after a comma runs both | confirmed, with a detail | `--reporter=dot`: the config's recording reporter does not run. `--reporter=list,<abs path with space>/reporter.mjs` and `--reporter list,<abs>` (two args): both reporters run. Repeated flag: only the **last** `--reporter` counts (`--reporter=line,<abs> --reporter=dot` drops ours) | 04-REQ-15: append the path to the **last** `--reporter` occurrence (or reject repeated flags). A path containing a comma cannot be passed this way (not tested; the value is split on commas) |
| V-06 | A status returned from `onEnd` sets the exit code in every version | confirmed | Passing tests + `onEnd` → `{status:'failed'}`: exit 1. Failing test + `{status:'passed'}`: exit 0. `interrupted`: 130, `timedout`: 1. No return: Playwright's own code | Manual mode can rely on `onEnd`. Note that returning `passed` also hides functional failures (in line with 04-D-09) |
| V-07 | Node's native TS loading works for the package config in ESM and CJS projects; error texts for extensionless imports and `tsconfig` aliases | confirmed, with warnings | Node 22.18.0 and 24.2.0, ESM and CJS: config with erasable syntax and `.ts` relative imports loads. Extensionless import: `ERR_MODULE_NOT_FOUND Cannot find module '<project>/cfg/helpers' imported from <project>/pw-perf.noext.config.ts`. Alias: `ERR_MODULE_NOT_FOUND Cannot find package '@cfg/helpers' imported from <project>/pw-perf.alias.config.ts`. `enum`: `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX TypeScript enum is not supported in strip-only mode`. Node 24.2 prints `ExperimentalWarning: Type Stripping is an experimental feature and might change at any time` (22.18 does not). CJS project (no `"type"`) with ESM syntax: `[MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of file://... is not specified and it doesn't parse as CommonJS.` | 01 §7.3 holds. The CLI should map the three error codes to fix hints (add `.ts`, no aliases, no `enum`) and keep Node warnings from looking like CLI errors |
| V-08 | `request.timing()` in Firefox and WebKit is comparable to Chromium | confirmed (Firefox on 1.65.1 only) | 20 sequential calls to a 200 ms endpoint after a warm-up. Median `duration`: Chromium 202.9-203.1 ms, WebKit 203.3-205.1 ms, Firefox 203.3 ms; `ttfb` medians 201.8-202.0 ms in all engines; max `duration` 206.5 ms. `requestStart`, `responseStart`, `responseEnd` never -1; no `timeSource: node` fallback. WebKit on 1.65.1 reports `connectEnd` without `connectStart` on reused connections (fields we do not use). An earlier run had one WebKit outlier of 245 ms on 1.57.0 | Best effort for Firefox/WebKit (D-13) holds; no extra accuracy warning required. Keep separating engines by `collector.browserName` |
| V-09 | In-flight requests can be finished safely in the `context` teardown with a time limit | partial | Request delayed 3 s, test ends at once. Wait in the `context` override teardown (before the built-in context closes): 500 ms → `PENDING`, test passes; 5000 ms → status 200, duration 3002.7-3004.4 ms. Wait in `_perfBuffer` teardown (after the built-in context closed): the request **never** settles, the full 5000 ms is wasted, sample `PENDING`. No `requestfailed` is emitted when a page or context closes with requests in flight (Chromium, WebKit, Firefox; both versions). A response whose body the page never reads gets `response` but never `requestfinished` and stays `PENDING` | 05-REQ-13 must wait **before** the built-in context closes, i.e. in the `context` override teardown (or the first such teardown for all trackers of the test), not in `_perfBuffer`. Trackers of already closed contexts/pages must not wait (listen to `close`). Consider using the `response` event so that a request with a response but no `requestfinished` is not `PENDING` |
| V-10 | `testInfo.attach` in a fixture teardown reaches `TestResult.attachments` in `onTestEnd` | confirmed | Present for passed, failed and timed-out tests. **Not** present when the teardown itself exceeds its time (see V-12 c) | As specified; the wait budget must keep the teardown inside its time, or the attachment is lost |
| V-11 | With `--list` Playwright skips `onEnd`, or calls it without tests | refuted (third option) | `--list` calls `onBegin` with **all** tests (4 of 4) and `onEnd` with status `passed`, no `onTestBegin`/`onTestEnd`. A status returned from `onEnd` still sets the exit code (`failed` → exit 1). The reporter only sees the list mode through the private constructor option `_mode: 'list'` | The reporter must treat "`onEnd` without any `onTestBegin`" as no run: write no report or outcome file, return no status. Otherwise manual `npx playwright test --list` fails. 04-REQ-22 (CLI ignores the outcome file with `--list`) stays |
| V-12 a | Chromium: CORS preflight is not a separate `Request` and its time is inside `timing().requestStart` | partial | 3 preflighted GETs (OPTIONS answered after 300 ms, GET after 100 ms): no `request` event with method OPTIONS (the server got 3 OPTIONS). `responseEnd` 404-407 ms, so `duration` **includes** the preflight. But `requestStart` 0.1-0.5 ms and `responseStart` ≈ 102-104 ms: these two are measured from the start of the real request, not from `startTime`. Simple cross-origin GET: `duration` ≈ 104 ms | `duration` covers the preflight (05-REQ-26 OK). `requestStart` does **not** show it, and `duration − responseStart` is not download time for preflighted requests. Docs: preflight is part of `duration`, invisible in `requestStart`/`ttfb` |
| V-12 b | `workers` set in a project can be overridden by the config copy from `withPerf()` | confirmed | Project `workers: 4` + global 4: 4 tests run concurrently. Global `workers: 1` (project still 4): 1 at a time. Global and project 1: 1 at a time. Project `workers` is a per-project cap below the global limit. `FullProject` in the reporter does not expose `workers` | Global `workers: 1` alone is enough; overriding per project is harmless. 04-REQ-19 cannot detect per-project `workers` from `FullProject`; only `FullConfig.workers` |
| V-12 c | Fixture teardown counts against the test timeout; the wait budget of 05-REQ-27 does not change the test result | refuted for the first half, confirmed for the second | Timeout 2000: body 500 + teardown 1000 → passed (1508 ms); body 1500 + teardown 1000 → **passed** (2506-2508 ms); body 500 + teardown 3000 → `timedOut` at 2503-2504 ms with `Tearing down "_perfBuffer" exceeded the test timeout of 2000ms.` Teardown runs in its own slot of `testInfo.timeout` that starts when the body ends. Budget `min(5000, timeout − elapsed since _perfBuffer start − 1000)` with timeout 3000 and body 1000: waited 609-870 ms, test passed, request `PENDING`. Without the cap: `timedOut`, `Tearing down "context" exceeded the test timeout of 3000ms.`, attachment lost | The 05-REQ-27 formula is safe but conservative. Correct basis: remaining = `testInfo.timeout` − time since the teardown phase started (when `use()` returned) − reserve. Fix the sentence "teardown counts into the test timeout" in 05-REQ-27 |
| V-12 d | Removing projects from the config copy does not break dependencies of the remaining ones | confirmed | Projects auth → setup → measured (teardown cleanup), plus other and other-teardown-owner/other-cleanup; measured = `measured`. Run: auth, setup, measured, cleanup, in that order, all passed; others not executed. `--project other`: exit 1, `Error: Project(s) "other" not found. Available projects: "auth", "setup", "measured", "cleanup"` | 04-REQ-18 as specified; the error text is Playwright's own |
| V-12 e | Failure text of aborted requests in WebKit (for `ABORT_FAILURE_TEXTS`) | answered | Navigation abort: Chromium `net::ERR_ABORTED`, Firefox `NS_BINDING_ABORTED`, WebKit `cancelled`. `route.abort()`: `net::ERR_FAILED` / `NS_ERROR_FAILURE` / `Blocked by Web Inspector`. `route.abort('aborted')`: `net::ERR_ABORTED` / `NS_ERROR_ABORT` / `Blocked by Web Inspector`. `route.abort('failed')`: `net::ERR_FAILED` / `NS_ERROR_FAILURE` / `Blocked by Web Inspector`. ## Not verified

- **Firefox on Playwright 1.57.0.** Its bundled build (`firefox-1497`) does not start on this
  host (macOS 27): `browserType.launch: Timeout 30000ms exceeded`, with
  `sandbox_extension_issue_file_to_process failed ... (Operation not permitted)` in the browser
  log; also outside the tool sandbox. Firefox 1.65.1 (`firefox-1572`) works and is covered.
- **Linux and Windows.** All runs are local on macOS arm64. Path handling with backslashes in
  `--reporter` (V-05) and signal handling are left to the CI matrix.
- **Node 22.18 for Playwright runs.** Only V-07 ran on 22.18; Playwright runs used Node 24.2.
- **`afterEach` hooks** were not part of the V-12 c check; whether they share the teardown slot
  is not measured here.
